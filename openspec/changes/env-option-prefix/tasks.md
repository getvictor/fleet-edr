# Tasks

- [x] Parse env's option prefix before collecting the assignment run, consuming the operand of options that take one and stopping at `--`.
- [x] Clustering follows BSD env, measured against `env(1)` rather than assumed: an operand-taking letter takes the REST of its own token when there is one, and the next argument only when there is not. `env -uS A=1 prog` therefore unsets S and applies A=1.
- [x] Validate the option letters against env's actual set (`-0iv`, `-C`, `-P`, `-S`, `-u`) and report nothing for an invocation env would refuse, since it execs nothing.
- [x] End the assignment run on whether a token assigns at all, not on whether a shell would accept the name, and narrow only the REPORTED set to well-formed assignments.
- [x] An unset of the variable being looked for reads as an unset, not an injection.
- [x] Mutation-tested: no option skipping, options never consuming an operand, the operand belonging to the first letter, `--` not ending option parsing, the refusal neutered, and the boundary tightened to the report filter. Two mutants initially "survived" because they preserved behaviour; the third attempt found that the refusal is only observable when the offending token itself carries an equals sign, and a test for that shape was added.
- [x] Two options end the run rather than being skipped: the one env refuses to combine with a command (measured: `env -0 A=1 /bin/sh` exits `cannot specify command with -0`) and the one carrying a command line as its value (measured: `env -S "/bin/echo hi" DYLD_INSERT_LIBRARIES=/tmp/x` prints `hi DYLD_INSERT_LIBRARIES=/tmp/x`, so the trailing token is echo's argument). Both previously reported a fabricated assignment.
- [x] The equivalence oracle no longer carries its own copy of env's option grammar. It models what the legacy Go matcher DID, which was to stop at the first non-assignment token including an option, so the property still measures the fix instead of agreeing with production by construction. The resulting divergence is asserted, not excused: it must be an env invocation with an option before its assignments, and the detection must be the side that fires.
- [x] The generator draws that env shape explicitly, because the structured branch always puts a verb between the flags and the operands and both sides stop at the verb. Mutation-tested across five seeds: removing the carve-out and inverting its direction each fail 5/5, and disabling the generator shape leaves the property passing vacuously, which is why a named example test pins the same behaviour deterministically.
- [x] An option's OPERAND is judged where env decides it statically: an unset of an empty name or one containing an assignment separator makes env exit (measured: `unsetenv A=B: Invalid argument`), as does an operand-taking option with no operand. Both previously reported a fabricated assignment.
- [x] The miss-over-fabrication exception is per VALUE, not per option: an empty working directory is refused whatever the host looks like (`chdir("")` always fails) and is decided, while a NAMED one is not. An earlier pass treated the option as host-dependent wholesale, which review corrected. The undecided half deliberately does not extend the preference, because its validity depends on the host and which env usually accepts. Suppressing it would be an attacker-selectable bypass (`env -C / DYLD_INSERT_LIBRARIES=x prog`), which is worse than the rare accidental fabrication. Stated in the spec so the asymmetry reads as a decision rather than an oversight, and the utility-path option is never refused by env at all (measured).
- [x] Mutation-tested, six guards: operand validity neutered, each half of the unset-name rule dropped, every operand validated like the unset, the missing-operand guard removed, and the attached operand not carried. The fourth needed a case the first pass lacked, because validating every operand changes nothing unless one would actually fail those rules; a directory name containing an equals sign is legal and env runs there, so that is the case that makes the guard observable.
- [x] An assignment whose NAME is empty makes env exit before executing anything (measured: `env =bad DYLD_INSERT_LIBRARIES=x prog` prints `setenv =bad: Invalid argument`), so such an invocation reports nothing at all. An earlier round reported what followed it, which was a fabrication. The discriminator is emptiness and not shell-legality, so this does not reopen the permissive boundary; both halves are mutation-tested, including a mutant that widens the guard to shell-legality and is caught by the row pinning `2+2=4`.
