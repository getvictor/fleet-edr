# Tasks

- [x] A stored document records whether it was shipped with the product or written by an operator.
- [x] Provenance is RECORDED when the document is stored, never derived from its path. #873 established that a rule's identity is its file stem rather than its path, and widened the load to walk the whole stored set precisely so authored content need not live under `imported/`. A prefix rule would contradict that and be chosen by the operator it describes: writing to `imported/mine.yml` would launder an authored rule into a vendored one, and a Detection Rule License attribution with it.
- [x] A caller cannot declare its own provenance. The per-document write records the operator's source itself, because how a document arrived is an observation rather than a claim.
- [x] Writing over a shipped document makes it the operator's, since the bytes are now theirs.
- [x] Attribution follows the recorded source: an operator's rule is credited to their deployment, a shipped rule keeps crediting upstream and its author. Asserted where it becomes visible, with fixtures that share a path prefix and an `author:` field so ONLY the recorded source distinguishes them.
- [x] The consequence that reaches persistence is covered too: `AlertOriginOf` is what every alert row stores, so a wrong credit there is durable and much harder to walk back than a catalog label.
- [x] The corpus records which shipped pack it holds, as a digest over the shipped content. Derived rather than declared, because a hand-maintained version has to be bumped by whoever edits the corpus and forgetting is silent: the deployment believes it is current while running different rules.
- [x] The digest covers the vendored half only, so an operator adding a rule does not make a deployment look out of date, nor deleting one make it look current.
- [x] The digest is recorded in the SAME transaction as the content it describes. Written separately it could fail on its own and leave a corpus whose content and stated identity disagree, silently.
- [x] Migration defaults existing rows to vendored, which is a statement of fact rather than a guess: every document predating this was written by the seed, since the authoring surface shipped after it and the only other writer had no production caller.
- [x] Mutation-tested, ten mutants, all caught. Two survived the first pass and both were weak TESTS rather than weak code: the pack-identity test drove `PutDocument`, which at the time recorded no digest at all, so it passed whatever the filter did (round 1 later made that path recompute, which would have masked the gap rather than closing it); and the "document moved" fixture changed sort order as well as path, so it would have passed with the path removed from the hash entirely.
- [x] Real-tool QA on the dev server. An authored rule was written deliberately to `imported/qa_provenance.yml`, the laundering path this change exists to close, and carrying an `author:` field naming someone else: it was recorded `authored` and credited `Locally authored` in the catalog, so neither the directory nor the rule's own text moved the credit. The migration was applied against the populated dev corpus, defaulting its 69 existing documents to vendored. For the durable half both that rule and a shipped one were put in alert mode and matched by ONE event on ONE host in ONE batch, raising two alert rows: `Locally authored` and `SigmaHQ, by Alejandro Ortuno, oscd.community`. Same event and same batch, so the recorded source is the only thing that separates them.
- [x] An unrecognised provenance is refused on the way in and on the way out. `Source.Valid` existed, and its own comment said a reader must not silently treat an unknown value as either known one, but nothing called it. The asymmetry is what makes it worse than either: an unknown value is not authored, so attribution credits it upstream, and it is not vendored, so the pack digest leaves it out. One such row would carry a licence claim about content nothing here can vouch for.
- [x] The pack identity follows a single-document mutation, not just a whole-corpus write. Writing over a shipped document reclassifies it as the operator's and deleting one removes it, so both change the shipped set while looking like they do not. Recomputed in `withVersionBump` for the reason the version bump lives there: neither mutation can forget it.
- [x] The operator's own rules are excluded from the alert-origin backfill (#870). Because a rule's id is its file stem, an operator who writes their own version of a shipped detection keeps that id, and crediting its historical alerts to them would permanently claim they wrote a detection they did not. That is this feature's failure mode pointed the other way, so the backfill deny-lists the local origin alongside the project's own.
- [x] The migration is forward-only, per ADR-0009. The Down section dropped both columns, which is worse here than the policy alone says: re-running the Up would recreate every surviving row defaulted to vendored, so an operator's rules would be credited upstream again. That is exactly the misattribution this migration ends, and it is not recoverable from the migration itself. `00012_alerts_origin.sql` is the precedent, a no-op Down for the same reason.
- [x] The backfill's third exclusion is in the spec that owns the requirement, not in this change's delta. Two in-flight deltas modifying one requirement is the collision that silently drops scenarios at archive time, so the scenario was added to `backfill-alert-attribution`, which still owns it until the release archive runs.
- [x] `Document.Source`'s contract was corrected rather than restated. It claimed a caller never declares provenance, which is true of the authoring surface and false of the whole-corpus replacement the pack upgrade and a restore both go through: those must be able to put an operator's rules back as theirs rather than relabelling them.
