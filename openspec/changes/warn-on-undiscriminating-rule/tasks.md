# Tasks

- [x] A predicate over compiled rule structure reports which of a rule's searches every event carrying their fields satisfies. It lives with the matcher, because nothing outside that package can answer a question about matching semantics without becoming a second implementation of them.
- [x] The answer names the searches rather than returning a boolean. A rule with six searches and one wildcard is a different problem from one that is wildcards throughout, and a bare "too broad" makes the operator find out which for themselves.
- [x] Exact rather than approximately alarming. `*` and `**` are reported; an EMPTY pattern is not, because it compiles to one empty segment which must account for every byte and therefore matches only the empty string, the narrowest pattern there is. A predicate written as "every segment is empty" would call it the broadest.
- [x] `*?*` is not reported either: its middle segment holds an atom, so it requires at least one character.
- [x] Composed the way matching is. The default field form is decided by ANY value matching, so one unrestrictive value settles it; `|all` needs EVERY value to match, so it takes all of them. A search's alternatives are an OR, so one undiscriminating alternative settles the search.
- [x] Says nothing about a `|re` pattern, deliberately. Deciding whether a regular expression matches every string is a question about that engine, and answering it wrongly in the reassuring direction would be worse than not answering. Pinned by a test so the silence is not later mistaken for coverage.
- [x] Surfaced as a WARNING through validation, not a refusal. An operator writing a deliberately broad hunting rule is doing something legitimate, and refusing would substitute our judgement for theirs on whether they meant it.
- [x] The predicate agrees with `match` rather than with my reading of the compiler: every pattern it calls undiscriminating is run against a spread of values including the empty string and must accept all of them, and every pattern it does not must reject at least one.
- [x] No rule in the vendored corpus trips it, measured rather than assumed: 0 of 66. A warning that fires on shipped content teaches operators to ignore it, so that is pinned as its own test.
- [x] Mutation-tested, six mutants, all caught. Two survived the first pass and both were real gaps: the `|all` branch had no test reaching it, and the explicit `absent` check was dead code (compileFieldTest returns before compiling any value, so an absent test always has zero values and the empty-list guard already answers it). The guard is gone and the invariant it leaned on is pinned instead.
- [x] Real-tool QA: submit a wildcard rule through the authoring API on the dev server and read the warning back.
