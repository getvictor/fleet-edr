## Why

ADR-0018 decides a phased Windows agent, and its first code step after the platform-aware contract is making the agent's portable core actually build and run on Windows. The Go core (queue, uploader, enrollment, command ledger, control client, health, metrics) is already platform-neutral, but a GOOS=windows build fails at two `syscall.Kill` sites, the host-identity source shells to macOS `ioreg`, and the default file locations are Unix paths. This change fills those seams with Windows-native implementations behind build tags so the agent compiles for windows/amd64 and windows/arm64, terminates processes with the platform's own primitive, derives a stable host id, and stores its data in the conventional Windows location. Behavior on macOS and Linux is unchanged.

## What changes

- Process termination becomes platform-native: the commander's kill default is `syscall.Kill` on Unix and `TerminateProcess` (via OpenProcess) on Windows. The reconciler's liveness probe (`kill(pid, 0)` on Unix) becomes an `OpenProcess`-based existence check on Windows that maps to the same ESRCH/EPERM/nil outcomes the pass classifier already expects.
- Host identity gets a Windows source: the registry `MachineGuid` under `HKLM\SOFTWARE\Microsoft\Cryptography`, a per-install GUID that is stable across reboots, readable without admin, and regenerated by sysprep (so cloned images do not collide). macOS keeps its IOPlatformUUID; other platforms return an error and rely on the `EDR_HOST_ID` override.
- Default file locations become platform-specific: `%ProgramData%\FleetEDR\` on Windows, the existing `/etc/fleet-edr.conf` and `/var/db/fleet-edr/` on macOS and Linux.
- A `build:agent:windows` task cross-compiles and vets the agent for windows/amd64 and windows/arm64, wired into the agent-test CI job as a compile invariant alongside the existing linux check.

Out of scope, tracked as follow-ups requiring a Windows environment to validate: the Windows service wrapper (`svc.Run` plus MSI `ServiceInstall`), Authenticode verification, and the ETW telemetry sensor (the agent currently uses the non-darwin stub receiver on Windows, so it enrolls and executes commands but produces no events yet).

## Capabilities

### Modified capabilities

- `agent-command-executor`: the process-termination command uses the platform's native primitive (SIGKILL on Unix, TerminateProcess on Windows) rather than being specified as SIGKILL only.
- `agent-configuration`: the agent resolves its default file locations from the platform (ProgramData on Windows, the existing Unix paths on macOS and Linux).

## Impact

- Code (agent): a kill seam in `agent/commander` (`kill_unix.go`, `kill_windows.go`) and a probe seam in `agent/reconcile` (`probe_notwindows.go`, `probe_windows.go`); a host-id split in `agent/hostid` (`hostid.go` becomes darwin-tagged, plus `hostid_windows.go` and `hostid_other.go`, with the package doc in `doc.go`); platform default paths in `agent/config` (`paths_darwin.go`, `paths_windows.go`, `paths_other.go`) wired into `config.go` and `conffile.go`.
- Build: `golang.org/x/sys` promoted from an indirect to a direct dependency; a `build:agent:windows` Taskfile target; a CI step running it in the agent-test job.
- Coverage: the Windows-only and non-primary-platform stub files (`**/*_windows.go`, `**/*_other.go`) are excluded from Sonar coverage since the coverage runners are macOS and Linux; correctness is gated by the cross-compile + vet invariant until a Windows CI runner lands.
- No wire, schema, migration, or server change. No behavior change on macOS or Linux: the Unix kill, probe, host-id, and path values are byte-identical to before the split.
